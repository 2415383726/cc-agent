# 政策研究

将知识库 search 用作一次深度研究，而不是一次关键词问答。围绕用户问题持续检索政策依据、适用范围、条件、程序、例外、时效和版本关系，直到关键结论得到足够交叉证据或明确出现证据缺口。最终输出清晰、美观且可追溯的研究报告。

知识库返回的是关键词召回的有限文本切片，不等于完整法规或当前有效的全部文件。任何结论都必须标明依据、适用条件和置信边界；不能声称“已穷尽全部政策”，不能把片段外内容补造为规则。

## 检索策略

直接调用 `search`，按研究问题迭代检索。不要只搜一次，也不要把同义词重复检索当作研究深度。

1. **界定问题**：从用户问题提取主体、事项、地区/单位、时间、目标（解释规则/判断资格/梳理流程/比较政策）。范围完全缺失时，用一次 `UserPrompt` 收集主题和适用对象；其余情况直接研究。
2. **首轮定位**：搜索核心事项词、制度名称、常见别名、主体词，识别可能的基础文件、实施细则、通知、问答和表单口径。
3. **分面追问**：围绕首轮证据继续搜索以下未覆盖内容：适用对象、资格/条件、程序/材料、审批权限、时限/日期、例外/禁止情形、责任/后果、过渡安排。
4. **依据链追溯**：对“依据某文件”“按照有关规定”等表述，检索被引用的上位或关联文件；对实施文件，检索是否存在配套细则。
5. **版本与冲突核验**：用文件名、发文时间、修订/废止/替代、同一事项不同表述等关键词检索。不能根据文件发布日期单独认定现行有效。
6. **反向检索**：针对拟形成的每个关键结论，搜索其反例、例外或限制条件，避免只收集支持性片段。
7. **停止条件**：核心结论已覆盖“规则 + 适用条件 + 来源”，且连续两轮没有新增关键依据；或知识库没有更多证据。停止后明确未能核验的内容。

每次检索记录：关键词、命中文件标题、可识别的发文/生效信息、原文要点、支持的研究问题和局限。相同文件的不同切片可互证上下文，但不能伪装成独立来源。

## 证据与写作规则

| 证据状态 | 可写的结论 | 不可写的结论 |
|---|---|---|
| 有明确文件标题和直接规则片段 | “检索到的《…》规定/明确…” | 片段未出现的完整条款或数值 |
| 有实施/解释性片段，未找到上位依据 | “实施口径显示…，上位依据待核验” | “法律/政策明确要求…” |
| 多份文件表述一致 | “当前检索到的多份材料一致指向…” | “已证明全国/全部单位统一适用” |
| 文件时间、效力或适用范围不明 | “检索材料不足以确认现行有效性/适用性” | “现行有效”“必然适用” |
| 文件间存在差异 | 并列展示差异、可能的对象/时间解释和待核验项 | 任意选择其中一份作为结论 |

- 短引必要原文，优先概括；每项结论紧邻来源标题和片段要点。
- 区分“政策文本规则”“对用户问题的解释”“建议核验动作”，不要混写。
- 不提供法律、组织人事或合规决定的替代意见；涉及具体个人资格、任免或处理时，仍需按正式流程和原文核验。

## 最终呈现

应用 `answers-ui` 和 `answers-charts` Skill。以可读的政策底稿风格呈现，不输出 HTML、链接按钮或模型自造引用。

1. **研究结论（Markdown）**：先回答用户问题；每条按“结论 → 适用条件 → 依据 → 边界”写，清楚标明已证实与待核验。
2. **研究范围（`cc-record`）**：主题、适用对象、时间口径、检索轮次、检索到的主要文件数、已覆盖维度和研究限制。
3. **规则矩阵（`cc-table`）**：每行一个问题点，列出规则结论、适用对象/条件、程序或时限、来源文件、证据状态、待核验项。不要把长原文堆入单元格。
4. **版本/口径对比（`cc-compare`，可选）**：仅当两至四份文件或版本就同一问题存在明确差异时使用，按适用范围、条件、程序、时间和结论对齐比较。
5. **政策沿革（`cc-timeline`，可选）**：只有文件时间、修订/替代关系和显示顺序均有证据时使用；不猜测废止或生效日期。
6. **数值规则图（最多 1 个 `cc-chart`，可选）**：仅在多个同口径政策门槛、期限或比例的差异本身是研究重点时使用 bar；通常规则矩阵比图表更合适。
7. **来源与缺口（Markdown）**：按文件标题列出本次使用的关键片段要点，并写明未找到、冲突或需查原文的事项。

## 交付前检查

- [ ] 已完成首轮、分面、依据链或反向检索，而不是只调用一次 search。
- [ ] 每个关键结论都有对应来源、条件和证据状态。
- [ ] 已检查时效、版本、适用范围和例外；未确认处没有被写成确定结论。
- [ ] 同一文件多切片未被虚构为多个独立来源。
- [ ] UI/Chart 仅用于澄清规则关系，未重复或夸大证据。
- [ ] 已明确知识库切片与正式原文核验之间的边界。
