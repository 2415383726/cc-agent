## Acceptance criteria

- [ ] 两个独立策略入口可被 Dify SDK 加载，使用当前 Session 的模型配置；Pi core/harness 初始版本均固定为 0.6.0。
- [ ] 问答实际经过 AgentHarness；文本及基本推理经所选输出 Adapter 产生有效 SDK 消息，不复制旧循环或在内核判断协议名。
- [ ] 通过真实 SDK 类型及受控会话验证同步调用上下文、asyncio 协调和流式交付；两次独立运行不会共享 Session。
- [ ] 输出带有新前缀、revision、run_id 和有效 Pi 分支/leaf 的基础快照；有效状态先于正常终态，摘要对应该快照。
- [ ] 用输出状态重建全部运行对象后可继续第二轮；恢复快照与 Dify history 不重复叠加；不导入旧 CC Agent 状态。
- [ ] 在相同能力和 fake 模型输入下，两种输出 Adapter 的模型请求与状态有效内容一致；AG-UI 基本文本/推理事件配对，原生输出能显示回答。
- [ ] 保留现有主要节点参数的明确输入契约；尚未实现的可选能力不得被宣称已完成。新插件使用独立身份，旧插件入口及旧会话保持可用。
- [ ] 从策略入口执行 fake 会话回归；普通模型错误输出安全失败，不能输出 traceback。

## Implementation context

- 按已确认规格实施：社区 Python Pi core/harness 0.6.0 为初始基线，单项目单插件双入口；Dify 持有模型/工具授权与唯一跨轮状态。内部只提供认知工具，不恢复已移除能力。
- 已有能力配置、语义事件和输出 Adapter 仅为初步骨架，需审查并测试后接入，不能据其存在跳过实现。
- 本票完成基础容量校验与拒绝非法状态；大状态裁剪、前端完整恢复由 06 扩展。功能验证包由 02 提供，本票不代表首版交付。
- 模型调用必须通过当前 Dify Session；不引入独立模型提供方、驻留服务、Node 或本地持久化。

## Verification

从两个策略入口各运行两轮 fake 模型会话，记录实际 SDK 请求、消息顺序及恢复状态；另验证真实 SDK 的调用上下文，避免仅用没有会话约束的纯 mock 证明可用。
