# 14: 远程审批恢复与未知结果核实

**What to build:** 需审批的远程工具在下一轮使用当前身份恢复，产物只交付一次；写操作结果未知时明确要求核实，不盲目重放。

**Blocked by:** [09 远程 MCP 身份隔离与产物交付](09-remote-mcp.md)；[13 工具审批、会话授权与策略重检](13-tool-approval.md)

**Version:** v2；用户已确认拆分并发布。按必要前置完成情况选择实施前沿；当前尚未实施。

**Parent:** [Agent 工作台规格 v2](../spec.md)

## Acceptance criteria

- [ ] 远程 pending 不保存连接或秘密 headers；下一轮重新连接、重新发现工具并按当前身份/策略/预算检查后执行。
- [ ] 远程批准/拒绝与普通工具保持合法配对及单一原调用结果，未执行尾部不重放，恢复结束后连接释放。
- [ ] 普通及恢复执行的直接 MCP blobs 只交付一次，Dify 已转发产物仍无第二转发；页面能关联原操作与新运行。
- [ ] 对 Dify 和 MCP 写操作的超时、断连、进程中止或保存失败保留 unknown 与稳定业务引用，不把未知转成未执行。
- [ ] 有业务查询或明确幂等契约时，核实结果后才能按契约继续；没有核实能力时保留未确认并提示处理，不自动重试。
- [ ] 验证业务已执行但响应丢失、执行后状态失败、工具已撤销/身份变化、重复批准等情况，避免再次发出写操作。
- [ ] 清楚区分重试模型与重放业务写操作，工作台显示未知、已核实、拒绝和失败，不声称插件提供跨崩溃恰好一次。

## Implementation context

- 组合 09 远程身份/产物与 13 恢复审批；unknown 规则同时适用于 Dify 工具，不因传输来源不同放宽。
- 可以保留业务 operation/job 短引用和查询工具，不借此引入 Tasks 系统、持久后台任务或额外网关。
- 当前只有少量骨架和依赖导入，前置票是否完成须检查实际验收记录。v2 是唯一范围依据，不恢复旧 AG-UI 双入口、Tasks、六命令或旧前端兼容要求。
- 每票包含自身完整行为及必要验证，优先从策略入口、真实 SDK 消息和浏览器观察；只给易变接入点补有限契约测试，不为每个内部 helper 建测试。

## Verification
