## Acceptance criteria

- [ ] 覆盖单块完整工具调用、delta、snapshot、ID/index 变化和交错调用；拼装后的工具名、ID、参数与实际 Provider 契约一致。
- [ ] 通过策略入口驱动完整工具执行，证明片段没有串入另一调用、重复合并或在 JSON 尚未完成时执行。
- [ ] 无效、截断或冲突参数产生可理解的错误结果且保持配对，不自动猜测具有副作用的业务参数。
- [ ] 文本与推理交替、多个模型轮次及工具阶段之间的 AG-UI 事件开闭正确，原生推理包装正确结束并防止内容注入关闭标签。
- [ ] 保留非流式回退、模型能力判断和既有 DeepSeek 思考兼容开关，不强制所有模型使用同一工具参数流模式。
- [ ] 准确转换用量及结束原因；两个输出 Adapter 不影响实际参数、调用次数或模型请求。
- [ ] 保留可重复执行的脱敏 Provider chunk 样本及契约来源，不存储凭证、用户原文或敏感业务参数。

## Implementation context

- 按已确认规格实施：社区 Python Pi core/harness 0.6.0 为初始基线，单项目单插件双入口；Dify 持有模型/工具授权与唯一跨轮状态。内部只提供认知工具，不恢复已移除能力。
- 已有模型 Adapter 的 Dify 兼容规则可经审查迁入；不复制旧 ModelRequests/AgentLoop 作为第二执行循环。
- 如部署样本暂不可取得，明确保留 Provider 实测未完成项，不能把人工构造 chunk 说成真实回放。
