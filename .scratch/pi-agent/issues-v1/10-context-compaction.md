## Acceptance criteria

- [ ] 测量实际送模内容，包括消息、系统提示、活动技能、工具 schema 和输出预留；固定内容本身超限时拒绝，不能偷偷裁剪用户请求。
- [ ] 自动及可供命令调用的手动压缩使用社区算法并更新 Pi 会话，摘要模型仍经当前 Dify Adapter 和统一预算。
- [ ] 普通、续写及最终请求遭遇可识别的上下文溢出时只压缩重试一次；相同恢复流程第二次溢出以 context_overflow 结束。
- [ ] 压缩/重试准确计入模型次数、token 和耗时；预算耗尽及时结束，不为总结绕过限制。
- [ ] 压缩前后的必要工具组、当前有效分支及引用可恢复；摘要不构成第二套权威历史。
- [ ] 安全清理无关分支或压缩前原文后进行实际导出—导入—继续调用验证；不能安全装入时沿用 06 的保存失败语义。
- [ ] 溢出重试只重试模型请求，不重放已经执行的工具；错误分类不会把任意传输失败当成上下文溢出。
- [ ] 两种输出策略的压缩活动、恢复后的答案及状态摘要一致；后续确认/技能真实组合在各票及最终集成中补齐。
