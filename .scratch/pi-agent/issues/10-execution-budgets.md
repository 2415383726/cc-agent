# 10: 执行预算、工具防护与用量统计

**What to build:** 用户配置调用、时间和 token 限额后，助手在预算内工作，工作台呈现准确次数及用量，失控重复调用受限。

**Blocked by:** [05 Dify 工具调用、通用工具卡与附件闭环](05-dify-tools-artifacts.md)

**Status:** ready-for-agent

**Version:** v2；用户已确认拆分并发布。按必要前置完成情况选择实施前沿；当前尚未实施。

**Parent:** [Agent 工作台规格 v2](../spec.md)

**Spec coverage:** US33、US34；V15。这是本票涉及的行为，不表示本票单独签收整个验收场景；最终平台证据由 17、18 补齐。

## Acceptance criteria

- [ ] 共享本轮运行账本计数所有实际模型请求和工具执行，包含普通、摘要、续写、最终请求及重试接入点；不只依赖 Pi max_turns。
- [ ] 开始新调用前检查模型/工具次数、协作式耗时、已报告 token；已执行结果保留，预算结束有准确原因与页面状态。
- [ ] 预算阻止的工具和同批尾部都得到明确未执行结果，下次模型前配对完整；预算耗尽不额外调用模型编写收尾。
- [ ] 启用重复工具与连续错误防护，结果大小/送模预算与展示限制分开；不截坏 JSON 参数或丢失必要 pending 数据。
- [ ] 实际请求估算包括系统指令、消息、技能、工具 schema 与输出预留；固定内容超限直接拒绝，不做无益摘要。
- [ ] 统计分开标识 provider 已报告、估计和未知用量，暴露实际模型/工具次数、结果类别与耗时，不伪造完整费用。
- [ ] 跨溢出重试保留同一账本，下一次 Dify 用户轮开始新预算并保留前轮统计；11、13、14 在本规则下扩展。
- [ ] 通过策略入口验证每个上限及统计、混合批次跳过和无额外模型收尾，界面展示与真实执行计数一致。

## Implementation context

- 复用固定版本最小请求前/批次末回调接缝，策略不依赖 UI 消费；不复制 Pi 执行循环。
- 限制耗时不代表强行取消同步 SDK 或远程写操作；副作用未知仍按 unknown 处理。
- 当前只有少量骨架和依赖导入，前置票是否完成须检查实际验收记录。v2 是唯一范围依据，不恢复旧 AG-UI 双入口、Tasks、六命令或旧前端兼容要求。
- 每票包含自身完整行为及必要验证，优先从策略入口、真实 SDK 消息和浏览器观察；只给易变接入点补有限契约测试，不为每个内部 helper 建测试。

## Verification

用可控模型、工具和时钟命中各项边界，观察实际请求次数、合法历史、状态及页面统计；为压缩/恢复提供可复用预算验证。
