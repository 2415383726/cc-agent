# 04: 复杂会话恢复与离线发布验收

Status: ready-for-agent

**What to build:** 用户在长会话、历史分页、缺失过程日志、停止断线和错误作品场景下仍能准确查看或恢复保留中的作品；交付配套插件和静态工作台，并在目标环境完成真实生成、交互、修改和历史重开的验收。

**Blocked by:** 03 — 内置 visualize 技能生成和修订作品。

依据：[规格 v1](../spec.md) 的历史/终态、错误与生命周期、版本配套、测试与完成判据。02 是传递依赖，无需重复列为直接阻塞。

## Acceptance criteria

- [ ] 扩展正常历史链路到分页加载、更早轮次、同名作品、同轮两块、重复事件及裁剪日志并存；所有作品按会话/消息/块/内容绑定，刷新或清除浏览器缓存后不会只剩最后一轮作品。
- [ ] 有完整平台回答但过程终态缺失时，用户可明确点击查看合法作品，同时保留“未确认”运行状态；打开作品不补造终态、不继续 Agent、不重放工具。历史保留遵循 Dify 保留策略，不承诺平台已删内容仍可恢复。
- [ ] 停止、失败、预算耗尽、断线、半成品和加载过程中的会话切换有明确状态；完整回答与终态到达次序变化不会提前启动、串会话或重复展示；不自动重 POST。
- [ ] 无效片段、未知内容/套件版本、超限、缺资产、脚本异常和初始化超时均可读降级，其他回答可继续阅读；异常后可以关闭或重新打开作品，不宣称任意恶意脚本的强 CPU/内存隔离。
- [ ] 重复展开/收起保留当前参数；刷新/重开回到初始参数。迟到尺寸/主题/错误消息、伪造消息、异常高度和循环尺寸更新不会污染当前会话，销毁释放 frame、监听器及 Blob URL 等关联资源。
- [ ] 在基础隔离已随 01 具备的前提下，对完整套件执行浏览器对抗回归：父 DOM/存储/凭据访问、连接、远程 script/style/image/font、fetch/XHR/WebSocket、frame 自导航/嵌套、表单、弹窗、下载和伪造展示消息均符合规格。网络观测发现外部请求即不通过，不以响应不可读作合格依据。
- [ ] 从实际配套发布物部署插件与静态工作台；清单检查内容/套件版本、资源哈希与许可一致，故意制造不匹配会让发布检查失败。运行时不需要公共 CDN、Node/Pi 后台或新增文件服务。
- [ ] 用真实模型完成“生成排队演示 → 本地调参 → 展开 → 刷新/重开 → 对话增加窗口 → 新旧作品恢复”的整条用户链路，覆盖浅深主题、320px/桌面宽度与主要键盘操作；live/history/replay 使用同一投影和宿主。
- [ ] 工作台测试、构建和静态检查，以及受影响插件测试/离线包检查通过。记录实际 Dify/provider、浏览器、插件/套件版本和资源无公网请求证据；测试 amd64 与生产 arm64 的适用证据按现有交付要求区分，未在目标架构运行的项目不得写成已验收。
- [ ] 汇总各票证据与规格覆盖关系，明确所有通过和仍未验证项；真实平台、隔离或历史恢复尚有缺口时不宣称功能完成，也不静默扩大部署架构或删减需求。

## Scope notes

本票包含复杂会话与故障场景的实际用户行为补齐，不只是跑一遍测试。03 是直接依赖，因为发布验收包含真实技能生成、对话修订及插件/工作台版本配套。基本隔离和完整性检查不允许拖到本票才实现。
