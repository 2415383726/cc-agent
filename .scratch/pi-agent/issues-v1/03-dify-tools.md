## Acceptance criteria

- [ ] 工具目录只使用本轮注入且可用的 Dify 工具，实际调用沿用当前 Session 及运行参数，不缓存跨用户工具身份。
- [ ] 工具默认串行；同批多调用、未知工具、错误参数及工具异常均在下一模型请求前形成一一对应结果，不执行无效调用。
- [ ] 由模型触发真实 fake 工具调用，再将结果回送 Pi 并产出最终回答；不只测试工具转换函数。
- [ ] 保留 repeated-halves 和语义 JSON 去重；Dify 工具产物沿用唯一交付路径，插件不新增二次转发。
- [ ] 两个入口显示相应工具进度/结果，show_tool_calls 只影响展示、不改变执行与状态；原生卡片对工具名、参数和结果正确转义。
- [ ] files 仅提供安全附件元数据；不提供文件内容读取、本地代码执行或任意路径访问能力。
- [ ] 结果有长度约束并保留必要引用；实际调用及成功/失败/未执行结果有可区分统计。
- [ ] 工具调用、结果、附件和卡片经过现有前端解释路径验证；旧插件回归保持通过。

## Implementation context

- 按已确认规格实施：社区 Python Pi core/harness 0.6.0 为初始基线，单项目单插件双入口；Dify 持有模型/工具授权与唯一跨轮状态。内部只提供认知工具，不恢复已移除能力。
- 只添加普通已获应用授权的执行闭环；需确认工具的持久暂停/恢复由 11 完成。外部工具永远不归内部认知工具执行器处理。
- 执行循环和消息配对归 Pi；异常仍需转为明确工具结果，不在输出 Adapter 中补造执行决策。
