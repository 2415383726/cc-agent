## Acceptance criteria

- [ ] MCP 确认暂停后关闭原连接；恢复时按本轮用户身份、headers 和工具目录重新连接，不从快照恢复原凭证。
- [ ] 获准远程工具仍服从当前策略/预算；恢复后结果替换原占位，同批未执行尾部调用不自动重放。
- [ ] 普通与恢复执行的 MCP blobs 都只经共同宿主交付一次；Dify 工具仍保持原有唯一产物路径。
- [ ] Dify/MCP 的写超时、连接中断或未能确定远端结果时明确标记 unknown，不能以普通失败或未执行状态自动重放。
- [ ] 使用稳定 operation/job 引用或业务幂等契约查询结果；不把每轮新 run_id 当作跨轮幂等键，也不由插件编造业务成功证据。
- [ ] 外部已执行但状态写回失败的场景不被描述为业务回滚；后续继续必须核实外部状态。
- [ ] 模型可见结果、执行元数据和用户表现区分成功、失败、未执行与 unknown；诊断不含用户凭证。
- [ ] 通过受控查询与写工具证明未知结果不会触发第二次提交，产物及会话在下一轮可继续。

## Implementation context

- 按已确认规格实施：社区 Python Pi core/harness 0.6.0 为初始基线，单项目单插件双入口；Dify 持有模型/工具授权与唯一跨轮状态。内部只提供认知工具，不恢复已移除能力。
- 工具原始结果分类和安全状态保存已有基础，本票补足远程恢复组合及业务未知结果的可观察行为。
- 业务服务需要提供查询/幂等能力；缺少该能力时报告限制，不用插件历史推断恰好一次。
