# 09: 远程 MCP 身份隔离与产物交付

**What to build:** 用户通过配置的远程 MCP 普通工具完成查询或生成产物，连接使用当前身份，结果和文件在工作台准确展示。

**Blocked by:** [05 Dify 工具调用、通用工具卡与附件闭环](05-dify-tools-artifacts.md)

**Status:** ready-for-agent

**Version:** v2；用户已确认拆分并发布。按必要前置完成情况选择实施前沿；当前尚未实施。

**Parent:** [Agent 工作台规格 v2](../spec.md)

**Spec coverage:** US13、US14、US15、US16、US17；V07、V18。这是本票涉及的行为，不表示本票单独签收整个验收场景；最终平台证据由 17、18 补齐。

## Acceptance criteria

- [ ] 仅接入授权远程 MCP 传输，不引入本地 stdio/脚本执行；只注册普通模型工具，App 专用能力正确过滤。
- [ ] headers 和连接由当前运行创建，不共享用户身份；日志、提示、状态和工具元数据均不含配置秘密。
- [ ] 串行受控执行复用 Dify 工具的配对/结果/事件接口，模型能消费正常和错误结果，页面有通用工具卡。
- [ ] 直连 MCP blobs 经共同交付点一次转发并正确展示，区别于 Dify 已自行转发的产物。
- [ ] 普通完成、错误、等待以及提前关闭都释放连接；单次传输异常不能污染另一个运行。
- [ ] 比较两个不同身份运行的实际调用，验证无 headers/工具清单/输出串用；不以全局客户端池掩盖生命周期。
- [ ] 通过真实远程测试服务或可控协议服务观察调用和释放，保留脱敏记录；审批后恢复和 unknown 由 14 完成。

## Implementation context

- 遵守远程 MCP 的单运行身份与资源边界，业务服务是既有授权服务，不是新增 Pi 常驻后台。
- 基本异常即需安全标记结果/清理，不能等 15 才处理；复杂未知结果核实在 14 扩展。
- 当前只有少量骨架和依赖导入，前置票是否完成须检查实际验收记录。v2 是唯一范围依据，不恢复旧 AG-UI 双入口、Tasks、六命令或旧前端兼容要求。
- 每票包含自身完整行为及必要验证，优先从策略入口、真实 SDK 消息和浏览器观察；只给易变接入点补有限契约测试，不为每个内部 helper 建测试。

## Verification

以两个身份查询/生成 blob，制造错误与提前关闭，观察服务端收到的身份、调用次数、连接释放和页面唯一附件。
