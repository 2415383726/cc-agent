# 07: 状态容量、历史与会话恢复

**What to build:** 用户刷新或切换对话后恢复正确历史和运行投影；状态损坏、过大或保存失败时明确失败，旧结果不会覆盖当前会话。

**Blocked by:** [05 Dify 工具调用、通用工具卡与附件闭环](05-dify-tools-artifacts.md)

**Status:** ready-for-agent

**Version:** v2；用户已确认拆分并发布。按必要前置完成情况选择实施前沿；当前尚未实施。

**Parent:** [Agent 工作台规格 v2](../spec.md)

**Spec coverage:** US24、US29、US30、US31、US32、US37；V04、V13、V14。这是本票涉及的行为，不表示本票单独签收整个验收场景；最终平台证据由 17、18 补齐。

## Acceptance criteria

- [ ] 在约 190KB 编码边界下导出/恢复 Pi 有效 entries、leaf、压缩引用和 tool-call/result 配对；编码与解压均有大小限制。
- [ ] 裁剪旧记录不改变当前有效投影；当前请求、必要尾部工具组和完整待处理数据优先，不能把模型上下文压缩当作存储缩小。
- [ ] 对代表性问卷/审批 pending 构造往返样本，保留完整参数与消费信息；实际问卷/审批闭环由 12、13 扩展。
- [ ] 无法安全保存时输出 state_save_failed，不发正常完成、不用空快照覆盖旧状态；摘要来自实际保存投影。
- [ ] state_ref 区分编码、输出与平台持久化未知；有效状态先于终态，下一轮读回能核对 revision/run ID，不把 revision 当原子锁。
- [ ] Dify 控制层完成会话映射、历史票据、实时/历史合并和过期结果丢弃；切换对话、慢历史回包和新对话 ID 恢复均不串线。
- [ ] 浏览器从 Dify 可恢复展示投影重建状态，缓存只用于草稿；没有可信终态的断流显示未确认且不自动重发。
- [ ] 通过策略状态往返与浏览器刷新/切换验证，坏版本、损坏数据、压缩膨胀和边界超限均安全失败，不重放已完成工具。

## Implementation context

- 基础状态已有 03，本票扩展大状态、交付失败及完整前端协调；不引入本地文件、MinIO 或第二权威存储。
- 不读取旧 CC Agent 快照；历史展示可以有投影，但答复/审批的权威校验始终由服务端 agent_state 完成。
- 当前只有少量骨架和依赖导入，前置票是否完成须检查实际验收记录。v2 是唯一范围依据，不恢复旧 AG-UI 双入口、Tasks、六命令或旧前端兼容要求。
- 每票包含自身完整行为及必要验证，优先从策略入口、真实 SDK 消息和浏览器观察；只给易变接入点补有限契约测试，不为每个内部 helper 建测试。

## Verification

多轮工具历史逼近容量边界，保存后销毁全部对象并恢复；再制造损坏/超限及浏览器历史竞态，核对实际快照、页面与请求次数。
