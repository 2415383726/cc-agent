# 18: arm64 生产目标离线与业务验收

**What to build:** 在生产目标或等价 arm64 环境独立安装最终单包并完成核心业务及恢复，取得该架构可交付的真实证据。

**Blocked by:** [16 Dify 兼容配置与静态工作台交付](16-dify-compatibility-static-release.md)

**Status:** ready-for-agent

**Version:** v2；用户已确认拆分并发布。按必要前置完成情况选择实施前沿；当前尚未实施。

**Parent:** [Agent 工作台规格 v2](../spec.md)

**Spec coverage:** US34、US41、US44；V21、V22。这是本票涉及的行为，不表示本票单独签收整个验收场景；最终平台证据由 17、18 补齐。

## Acceptance criteria

- [ ] 在干净 Linux arm64 与目标 Dify/Python 3.12 执行器中，按生产约束离线安装最终一个对应架构 difypkg，无预装 Node 或依赖下载。
- [ ] 逐项核对实际依赖、资源/许可、版本与 hash，运行不借用 amd64 环境、开发虚拟环境或未经说明的架构转换。
- [ ] 实际执行模型、Dify/MCP 工具和产物、技能、预算、压缩/一次溢出、问卷/审批与跨轮恢复代表业务链路。
- [ ] 验证刷新/历史、权限变化、重复答复、unknown、停止/断流与保存失败，观察真实操作次数和状态交付语义。
- [ ] 对 V21 与 arm64 业务 V22 提供可复现运行证据，并核对 V01—V19 在生产目标的组合表现；wheel 解析或 amd64 通过不代签。
- [ ] 记录该架构包大小、安装启动、模型/工具次数、已报告用量及耗时，说明环境差异，不用另一架构时延推断本机性能。
- [ ] 环境缺失、失败或未核实项明确列出，不以标记完成绕过；本票不自动实施生产切流、旧会话迁移或不可逆操作。

## Implementation context

- 与 17 互不阻塞；两个架构都依赖最终版本/配置交付，但首版完整验收需要各自真实证据。
- 允许生产目标等价受控环境，不要求直接在生产执行写操作；业务服务用受控样例及明确授权。
- 当前只有少量骨架和依赖导入，前置票是否完成须检查实际验收记录。v2 是唯一范围依据，不恢复旧 AG-UI 双入口、Tasks、六命令或旧前端兼容要求。
- 每票包含自身完整行为及必要验证，优先从策略入口、真实 SDK 消息和浏览器观察；只给易变接入点补有限契约测试，不为每个内部 helper 建测试。
