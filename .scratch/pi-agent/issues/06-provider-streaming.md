# 06: 模型流兼容与工具参数正确执行

**What to build:** 不同 Dify 模型输出文本、推理和交错工具参数流时，工作台保持正确内容，真实工具只收到完整且准确的参数。

**Blocked by:** [05 Dify 工具调用、通用工具卡与附件闭环](05-dify-tools-artifacts.md)

**Status:** ready-for-agent

**Version:** v2；用户已确认拆分并发布。按必要前置完成情况选择实施前沿；当前尚未实施。

**Parent:** [Agent 工作台规格 v2](../spec.md)

**Spec coverage:** US06、US07、US08；V05、V09。这是本票涉及的行为，不表示本票单独签收整个验收场景；最终平台证据由 17、18 补齐。

## Acceptance criteria

- [ ] 覆盖完整调用、delta、snapshot、交错 index、后到/省略 ID、名称片段和多调用；参数流模式明确配置，不按 JSON 前后缀猜模式。
- [ ] 重复字符在 delta 中保留，snapshot 替换而不拼接；只在完整校验后执行，不将 partial 参数视为可执行动作。
- [ ] 支持实际推理、文本内容块、provider 已报告用量与必要非流式回退；页面最终消息覆盖临时消息，ID/内容块对应正确。
- [ ] 坏 JSON、缺失参数、provider 异常或流中断产生安全失败与合法配对，不触发部分参数工具调用。
- [ ] 工具执行事件与最终 tool result 合并为同一执行，不因模型/工具流交错新增重复卡片或答案。
- [ ] 通过策略入口回放真实脱敏 provider 样本并检查工具实际参数/次数、后续模型历史和页面结果；不只测试字符串转换函数。
- [ ] 记录支持的取样版本、参数模式与已知限制；无 partial 或推理时仍准确呈现普通运行状态。

## Implementation context

- 本票接入的是 Dify 模型适配，不是直接采用社区默认 LangChain adapter 的时序；Python Pi 与 TS 字段差异只在边界映射。
- 压缩溢出统一额度由 11 完成，停止/断流的全链路收尾由 15 整体验证；本票自身异常不得留坏历史。
- 当前只有少量骨架和依赖导入，前置票是否完成须检查实际验收记录。v2 是唯一范围依据，不恢复旧 AG-UI 双入口、Tasks、六命令或旧前端兼容要求。
- 每票包含自身完整行为及必要验证，优先从策略入口、真实 SDK 消息和浏览器观察；只给易变接入点补有限契约测试，不为每个内部 helper 建测试。
