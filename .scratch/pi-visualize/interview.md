# Pi Agent 交互可视化：设计访谈

日期：2026-10-29。状态：产品范围与测试边界已确认，已发布 [规格 v1](spec.md)；未开始产品实现。

## 已确认

- 第一版目标：助手讲解时生成可操作的图解、模拟器、小工具（首轮 Q1：A）。
- 展示入口：自有 Pi Agent 工作台（首轮 Q2：A）。
- 图内交互仅在本地完成，不向助手发消息或调用工具（第二轮 Q3：A）。
- 刷新或重新打开会话后恢复生成的作品，交互参数回到初始值（第二轮 Q4：A）。
- 运行时不访问公网资源，所需资源随工作台部署（第二轮 Q5：A）。
- 允许助手判断有助于理解时主动生成，也支持用户明确请求（第三轮 Q6：A）。
- 第一版支持会话内查看、展开与交互，暂不提供独立 HTML 下载（第三轮 Q7：A）。
- 修改通过普通对话提出并生成新作品，旧作品保留（第三轮建议，用户答复“都同意”）。
- 综合 ChatGPT、本会话可用 visualize、ZCode visualize 等经验，内置技能、样式与配套能力（用户随后补充）。
- 主验收通过工作台覆盖生成、本地交互、展开、刷新/历史恢复及对话修改；辅以必要的技能、内容协议、历史合并与隔离测试（用户确认“符合，按此写入规格”）。

## 现有约束与证据

- 延续 Dify 宿主路线；更换运行底座需另有实际需求依据。见 `docs/adr/0009-keep-dify-host.md`。
- 工作台是静态 Vue 应用；当前 Markdown 明确关闭原始 HTML，尚无生成内容执行宿主。见 `pi_workbench/src/projection/markdown.ts` 与 `pi_workbench/README.md`。
- Pi 显示事件有 24,000 字节预算，工具结果展示有 8,000 字符裁剪；不能假定普通工具卡能无损承载完整可视化代码。见 `pi_dify/pi_agent/contract.py`。
- Pi 会话状态有容量与裁剪限制，完整可视化内容的保存和恢复需要单独验证。不能将浏览器缓存默认为 Pi 跨轮权威。
- 既有 ZCode 研究可供参考，但不能视为 DeepSeek Harness 的实现证据。见 `.scratch/pi-agent/zcode-genui-runtime-research.md`。

## 当前状态

产品范围已确认，规格按本地问题跟踪约定发布为 `ready-for-agent`。原生回答完整性、历史恢复及浏览器隔离仍需在实施中验证，不代表已经跑通。设计背景见 [design.md](design.md)，实施依据见 [spec.md](spec.md)。

## 候选技术路线（待验证，不是用户已决策）

- 最小路线：作品源码作为最终回答中的专用 fenced block，由工作台在回答完成后识别并交给隔离宿主；Dify 原生回答历史保存作品。这样可能不需新增文件服务。
- 备选路线：通过 Dify 原生 blob 交付 HTML 文件，使用历史附件恢复。需要验证文件归属、稳定身份、访问与 URL 更新方式。
- `runtime.py::_finalize` 的原生文本输出发送完整 `answer`；`message.end`、`run.state`、`last_answer` 等投影均有裁剪。若采用回答内嵌路线，必须按消息逐条合并完整平台回答，不能依赖裁剪后的事件或最近一次状态。
- 无论采用哪条路线，作品展示内容不成为 Pi 状态权威；工作台不得由图内交互授予工具权限。

## 已完成的源码调查

- Pi Agent 技能/工具/显示契约接缝、完整回答及历史合并限制。
- DeepSeek Harness 文件交付与 HTML 预览链路，及其文件声明不保存内容的限制。
- ZCode visualize 的技能、样式说明与 CSS、页面 API、固定 vendor 清单及许可。
- 本会话可用 visualize 技能的生成规范、基础样式/控件与平台专用桥边界。
