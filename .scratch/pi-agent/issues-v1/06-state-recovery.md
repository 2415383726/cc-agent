## Acceptance criteria

- [ ] 使用独立 piagent-state:v1:gzip-base64: 封装，验证版本、编码长度及解压上限，拒绝损坏输入且不静默清空已有状态继续业务调用。
- [ ] 输出及再次导入 Pi 当前有效分支、必要引用、active leaf 和应用状态；不依赖进程驻留，且不维护第二份送模历史。
- [ ] 在约 190KB 约束下执行安全容量检查和可证明保持投影的无关记录清理；不能安全容纳时明确失败，不丢必要工具组、应用状态或待处理参数。
- [ ] 可用旧状态不会被伪造空快照覆盖；状态错误/容量失败产生失败终态而非 agent_finished 正常完成。
- [ ] 状态有效性检查和输出先于终态；state_summary 对应实际快照，state_ref 区分编码、已输出与平台持久化未知。
- [ ] 现有前端可解码新前缀以恢复 revision/run_id/状态/问题投影，同时保留旧前缀恢复，不要求 Pi Agent 导入旧插件状态。
- [ ] 保留会话 ID、线程映射、历史票据及 stale-result 规则；无可信终态按未确认完成处理，旧结果不能覆盖当前会话。
- [ ] 覆盖接近容量边界的工具历史与应用状态往返；后续技能/确认票必须扩展真实入口场景，不能只靠预置状态宣称全功能通过。
