# 12: AskUser 问卷暂停与跨轮答复

**What to build:** 助手提出多题问卷后确定性等待，用户刷新仍可作答，下一轮恢复同一任务；重复、过期或无效答案不会触发继续执行。

**Blocked by:** [07 状态容量、历史与会话恢复](07-state-history-recovery.md)；[10 执行预算、工具防护与用量统计](10-execution-budgets.md)

**Status:** ready-for-agent

**Version:** v2；用户已确认拆分并发布。按必要前置完成情况选择实施前沿；当前尚未实施。

**Parent:** [Agent 工作台规格 v2](../spec.md)

**Spec coverage:** US22、US23、US24、US25、US26、US29、US37；V01、V10、V11、V13。这是本票涉及的行为，不表示本票单独签收整个验收场景；最终平台证据由 17、18 补齐。

## Acceptance criteria

- [ ] 将 01 的可操作问卷接入真实提问工具结果，含稳定问卷/题目/选项 ID、类型、校验约束和状态；覆盖单选、多选、文本及多题。
- [ ] 提问工具完成问题提出，原结果保留问卷；同时保存权威 pending，不持有进程 Promise，不在答复时把旧结果替换成答案。
- [ ] 提问后串行 gate 阻止混合批次尾部真实工具，core 补齐未执行结果；批次末停止，暂停后零新增模型请求，不能只依赖 terminate 或提示。
- [ ] 有效状态先于 awaiting_user 终态，当前问卷安全投影保留在 Dify 历史/状态可恢复路径；刷新或重建不依赖草稿缓存。
- [ ] 显式映射交互类型、问题 ID、结构化答案/取消到应用节点和插件；服务端以当前 pending 校验，而不是依赖按钮禁用。
- [ ] 有效答案作为新用户消息加入 Pi，消费当前 pending 后继续；历史保留问题/答案及相关 ID，新运行预算与前轮统计区分。
- [ ] 缺失、错误题目/选项、过期或已消费答案不执行工具/继续模型，返回可理解拒绝；明确取消结束本次等待并记录取消，不执行尾部操作，后续工作由新的用户请求触发。
- [ ] 界面具备键盘操作、提交等待/失败恢复及防重复；消费记录保存后再次提交可拒绝，不能把并发或保存失败情形宣称为原子/恰好一次。
- [ ] 覆盖 ask+普通写工具混合批次、实例销毁/刷新、正确/错误/重复/取消、再次提问及保存失败的策略与浏览器完整闭环。

## Implementation context

- 只实现普通信息提问，不赋予工具执行许可；审批由 13 单独完成。无需 Dify 原生 Human Input 节点或社区长期 waiter。
- 源 UI 投影必须保留问卷安全结构，不能在转换 tool result 时丢掉 details，也不能只显示 JSON 就宣称表单可用。
- 当前只有少量骨架和依赖导入，前置票是否完成须检查实际验收记录。v2 是唯一范围依据，不恢复旧 AG-UI 双入口、Tasks、六命令或旧前端兼容要求。
- 每票包含自身完整行为及必要验证，优先从策略入口、真实 SDK 消息和浏览器观察；只给易变接入点补有限契约测试，不为每个内部 helper 建测试。

## Verification

通过真实 Dify 输入映射提出并回答问卷，销毁实例和刷新后继续；量测暂停后的模型请求与尾部实际工具执行均为零，再回放重复/过期提交。
