# 16: Dify 兼容配置与静态工作台交付

**What to build:** 部署者可按明确配置在声明支持的 Dify 版本中使用静态工作台和新插件，完整功能输入/输出映射可复现，旧应用继续可用。

**Blocked by:** [04 双架构离线单包与基本问答启动](04-offline-bootstrap.md)；[08 应用技能激活、资源读取与过程展示](08-skills-lifecycle.md)；[11 自动压缩与一次上下文溢出恢复](11-context-compaction.md)；[15 停止、断流与安全失败收尾](15-stop-failure-security.md)

**Status:** ready-for-agent

**Version:** v2；用户已确认拆分并发布。按必要前置完成情况选择实施前沿；当前尚未实施。

**Parent:** [Agent 工作台规格 v2](../spec.md)

**Spec coverage:** US02、US13、US42、US43、US44、US45；V04、V18、V19。这是本票涉及的行为，不表示本票单独签收整个验收场景；最终平台证据由 17、18 补齐。

## Acceptance criteria

- [ ] 提供新插件节点/应用配置和结构化交互字段的明确映射，涵盖模型、query、工具、文件、技能、MCP、运行配置与 agent_state。
- [ ] 实际验证生产目标 Dify 1.15.0 和声明最低兼容版本的关键事件、状态、历史、附件及问卷/审批路径；最低声明不低于原 1.7.0，不静默提高要求。
- [ ] 新前端生成可静态托管构建物，记录托管位置、Dify 连接配置、版本配对及升级方式，无 Node/Agent 后台或公网运行资产。
- [ ] 将最终新增依赖/资源持续纳入 04 的两架构离线构建，不重新依赖开发机环境；记录插件与静态资产 hash/来源/许可。
- [ ] 以完整业务链路检查工具/技能/压缩/问卷/审批/恢复的组合，显示契约有版本处理与通用兜底，不遗漏最终文本、文件或历史。
- [ ] 旧 CC Agent 与旧前端回归仍可用，新插件独立身份和新会话，不迁移旧快照或修改旧 Tasks/协议。
- [ ] 发布文档不宣称全部 RPC、双入口、原生 Human Input、完全事件重放或恰好一次；记录真实版本限制和未验证项。
- [ ] 提供可复现的版本/配置集成记录和静态部署操作；真实平台不可用则保留未完成，最终离线业务验收分别由 17、18 完成。

## Implementation context

- 本票直接依赖的是离线构建、技能、压缩与复杂失败完整路径，其他所需能力已在其传递依赖中；不人为再列所有前序票。
- 不新增产品范围或重复实现前端，只完成已选配置、版本与最终资源交付的跨功能集成。
- 当前只有少量骨架和依赖导入，前置票是否完成须检查实际验收记录。v2 是唯一范围依据，不恢复旧 AG-UI 双入口、Tasks、六命令或旧前端兼容要求。
- 每票包含自身完整行为及必要验证，优先从策略入口、真实 SDK 消息和浏览器观察；只给易变接入点补有限契约测试，不为每个内部 helper 建测试。

## Verification

在声明版本按交付配置重建应用并跑关键链路，部署静态构建物检查运行网络依赖，再验证原插件/旧前端回归及包资产清单。
