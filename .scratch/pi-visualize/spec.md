# Pi Agent 内置交互可视化规格 v1

Status: ready-for-agent

发布日期：2026-10-29。范围来源：已确认的设计访谈，以及用户补充的“综合参考 ChatGPT、ZCode 的 visualize，内置技能和样式”。测试边界已由用户确认。本文为实施依据；发布规格不代表功能已实现或真实平台已验收。

## Problem Statement

用户已经能在 Pi Agent 工作台完成对话，但遇到需要观察变化、比较条件或理解过程的问题时，文字和静态图片难以表达。他们希望像 visualize 一样，在助手的回答中直接操作图解、模拟器和小工具，改变参数后立即看到结果。

仅增加一个可以执行 HTML 的区域不足以交付这种体验：模型还需要知道何时生成、如何组织图形、使用哪些控件和样式；工作台需要提供稳定的主题和运行环境。用户不希望每次都要求模型重新创造整套样式，也不希望内网部署依赖公共 CDN。

作品还应当随会话保存。当前过程日志和 Pi 状态有裁剪限制，直接从工具结果或最近一次状态恢复作品，会造成刷新后内容残缺、旧作品丢失或归入错误回答。

## Solution

为 Pi Agent 内置一套交互可视化能力，由四个配套部分组成：**应用技能与参考资料、主题样式及基础控件、本地运行资源、工作台隔离宿主**。综合参考本会话可用的 visualize 技能、ZCode visualize 的开源内容与宿主设计，以及 DeepSeek Harness 的 HTML 交付/预览经验，适配现有 Dify 宿主和静态 Vue 工作台。

助手在交互展示有助于理解时可以主动生成，用户也可以明确请求。作品与回答一起出现，支持图内调参、播放、切换、内联查看和展开。图内操作仅改变本地展示；不发起模型轮次或业务工具调用。

第一版将完整作品内容作为最终原生回答的一部分交给 Dify 保存，工作台识别专用内容块后隔离运行。刷新、重开会话或加载更早历史时重建原作品，交互参数回到初始值。用户通过普通对话提出修改，得到新的作品，旧作品保持可查看。

可视化资源随工作台部署，技能及参考资料随插件交付。第一版继续采用现有 Pi Harness、Dify 模型/工具边界及静态工作台，不增加常驻 Agent 后台或独立产物存储服务。

## User Stories

1. 作为用户，我希望直接操作助手生成的图解，以便理解文字难以表达的变化。
2. 作为用户，我希望明确请求可视化讲解，以便选择适合自己的理解方式。
3. 作为用户，我希望助手在确有帮助时主动生成可视化，以便不必预先知道该用什么图。
4. 作为用户，我希望普通事实和简单问答保持简洁，以便可视化不会干扰阅读。
5. 作为用户，我希望作品出现在对应回答的位置，以便把说明与图形联系起来。
6. 作为用户，我希望作品首次出现就有意义，以便无需先操作多个控件才能看见内容。
7. 作为用户，我希望拖动滑块后图形立即变化，以便理解参数与结果的关系。
8. 作为用户，我希望使用选项、开关和按钮控制演示，以便比较不同条件。
9. 作为用户，我希望演示在适用时可以暂停和重置，以便按自己的速度观察。
10. 作为用户，我希望只有必要的控件和说明，以便注意力集中在主要图解上。
11. 作为用户，我希望图形有清楚的标签、单位和图例，以便正确理解含义。
12. 作为用户，我希望图内操作不会自动向助手发消息，以便自由试验而不产生额外轮次。
13. 作为用户，我希望图内按钮不会执行后台业务操作，以便展示交互的作用范围清楚。
14. 作为用户，我希望展开作品后获得更大的空间，以便观察细节。
15. 作为用户，我希望展开和收起时保留当前参数，以便观察不会被打断。
16. 作为用户，我希望刷新后重新打开原作品，以便继续查看已有回答。
17. 作为用户，我希望重开作品时使用初始参数，以便得到可重复的起点。
18. 作为用户，我希望更早轮次和历史分页中的作品同样可用，以便长期对话不只保留最后一幅图。
19. 作为用户，我希望切换会话后不会混入其他作品，以便对话与内容对应可信。
20. 作为用户，我希望通过对话要求修改作品，以便无需学习专门编辑器。
21. 作为用户，我希望修改后仍能查看旧作品，以便比较前后结果。
22. 作为用户，我希望旧源码已不在模型上下文时得到明确说明或重新生成，以便不会误以为完成了精确编辑。
23. 作为用户，我希望生成中的半成品不会开始运行，以便避免闪烁和错误操作。
24. 作为用户，我希望停止或断线后准确显示作品状态，以便不把残片当成完成品。
25. 作为用户，我希望无效或超限作品有可读兜底，以便整段回答仍能阅读。
26. 作为用户，我希望多个作品的样式与工作台一致，以便不会每次面对不同的控件语言。
27. 作为用户，我希望浅色、深色主题下图形均清晰，以便在自己的显示偏好下阅读。
28. 作为用户，我希望窄屏下控件和标签不重叠，以便移动设备也能操作。
29. 作为键盘或辅助技术用户，我希望控件有名称、焦点和状态提示，以便不依赖鼠标操作。
30. 作为对动画敏感的用户，我希望演示尊重减少动画偏好，以便舒适地阅读。
31. 作为内网用户，我希望图表、图标、样式和字体不依赖公网，以便部署后稳定打开。
32. 作为应用维护者，我希望内置可视化技能与按需参考资料，以便模型得到稳定的生成指导。
33. 作为应用维护者，我希望模型复用内置样式、图表与图标能力，以便减少重复代码和输出体积。
34. 作为应用维护者，我希望技能描述的控件与实际宿主完全一致，以便模型不会调用不存在的能力。
35. 作为应用维护者，我希望作品无法获得工作台凭据或业务权限，以便内容执行与 Agent 授权分离。
36. 作为部署者，我希望技能和静态资源都有明确版本、来源与许可，以便离线交付和升级可追溯。
37. 作为维护者，我希望新版本还能识别第一版作品，以便历史会话不会随样式升级失效。
38. 作为维护者，我希望主要通过真实工作台和 Dify 验收整条链路，以便不把孤立组件演示当成功能完成。

## Implementation Decisions

### 1. 延续现有宿主与状态边界

- Pi Harness 保持现有执行、模型、工具和压缩职责。可视化是回答内容与展示能力，不新增调度循环、通用脚本工具、文件系统或会话状态后端。
- Pi 状态继续作为 Agent 跨轮权威；原生 Dify 回答保存作品展示内容。浏览器内参数不进入 Pi 状态，不构成工具授权。
- 模型与 Dify 仍需可达。“无公网资源”指作品和工作台运行资源，不宣称模型推理离线。
- 本轮实施仅涉及 Pi Agent 及其工作台，沿用已有独立插件、有限显示契约与 Dify 宿主决策。

### 2. 内置 visualize 应用技能

- 技能以 `visualize` 名称随插件发布，使用现有发现、激活、受限资源读取与资格恢复机制；支持模型选择与已有用户技能调用入口。
- 技能描述覆盖交互讲解、参数对比、过程演示、小型模拟器等触发分支。技能入口只保留每次生成都需要的步骤和规则，样式目录、图表说明与示例按需读取。
- 技能必须指导模型先判断表达方式：普通事实直接回答，表格请求用表格；只有交互能帮助理解时生成作品。静态结构可直接文字表达；不把新增 Mermaid 渲染能力作为本功能前提。
- 核心指导包括：有意义的首屏、一个主要图解、必要控件、真实本地反馈、可读标签/单位、窄屏布局、主题适配、键盘操作、减少动画，以及作品体积预算。
- 提供与实际宿主一致的内容协议、样式/控件说明、内置库 API 和少量完整示例，至少覆盖原生 SVG 交互讲解、使用本地 D3 的图表交互、基础控件组合。
- 模型使用宿主提供的样式和资源，不在回答中复制整套 CSS、图表库或图标源码。插件的模型可读资源只包含必要文档和示例，第三方运行资产放在工作台发布物中，避免进入技能全文扫描和模型上下文。
- 生成前后的自检只要求当前能力能够完成的检查。技能不能声称已运行浏览器测试，也不能照搬上游要求模型写本地文件、运行 Python 渲染脚本的步骤。
- 不提供伪造的 OpenAI/ZCode 全局桥。技能只描述本项目真实存在的本地能力，不引导图内发消息、保存跨轮参数或调用工具。

### 3. 内置样式与基础控件

- 工作台维护一套有版本的可视化运行套件。宿主组装文档并注入样式、主题与必要运行资源，模型只提供作品片段。套件与普通聊天样式隔离，作者样式也不得影响主页面或其他作品。
- 公共主题契约覆盖背景/文字、卡片/浮层、主次操作、弱化文字、边框、输入框、焦点、错误色、六个稳定图表系列色、字体与字号。映射到工作台主题；图形、SVG、canvas 和控件均需适配主题变化。
- 提供常用布局、文字、按钮、表单和表格样式。第一版目录至少包括 `.viz-row`、`.viz-grid`、`.viz-controls`、必要的 `.card`/数值摘要、`.btn` 及主/弱操作、`.form-label`、`.form-control`、`.form-select`、`.form-range`、复选/开关、`.table`/响应式表格、弱化文字及屏幕阅读辅助类。
- 基础可复用行为包括可访问的 tabs、tooltip 和图标初始化。tabs 同步可见面板与选中状态；tooltip 支持键盘/触摸且不承载唯一的必要信息。原生 slider/select/toggle/button 的业务演示逻辑由片段内本地脚本完成。
- 图解默认紧凑、少装饰；图表无需额外卡片包裹。共享控件拥有统一间距、焦点、触摸目标和禁用态，模型无需重新设计整套控件。
- 第一版不复制上游所有 widgets。日历、设计变体轮播和 Tweak 参数编辑面板列为后续扩展；已提供的 API 才进入技能目录。普通演示的原生滑块等不依赖 Tweak。
- 浅/深色、320px 起的窄屏、键盘操作与减少动画属于套件验收范围。canvas 接收解析后的主题颜色并在主题变化时重绘。

### 4. 固定版本的本地资源

- 第一版提供原生 HTML/CSS/JS、SVG/canvas，以及本地 D3 7.9.0 和 Lucide 1.17.0。它们是已调查的 ZCode 资源基线，不代表追踪最新版本；实际交付需保留对应依赖锁定与许可证。
- 若 tooltip 适配直接复用 Floating UI，则固定 Core 1.7.3 / DOM 1.7.4；选择更小的实现也可以，但模型面对的 tooltip 契约保持一致。
- 作者通过协议声明内置库标识，由宿主在作者脚本前提供所需全局；不允许作者提供任意资源 URL、包名或导入地址。图标初始化在内容就绪后执行。
- 所有 CSS、JS、图标资源随静态工作台交付；字体使用系统字体。作品内的数据和素材应当自包含且在预算内，第一版不开放在线图片、地图瓦片、远程字体或数据请求。
- 宿主直接使用本地资产，不依赖 Electron URL 拦截，不因缺少资源而回退到 CDN。未知库或缺失资产明确失败并保留文本兜底。
- 发布清单记录套件版本、资源标识、实际库版本、校验和、来源与许可。插件技能文档和工作台套件共同声明支持的协议/套件版本，发布检查发现不一致即失败。

### 5. 回答内嵌内容协议

- 第一版使用专用 `pi-visualize` fenced block；普通 HTML/JS 代码块继续作为代码展示，用户消息或工具结果中的同名文本也不自动执行。
- 块内采用原始 HTML 片段，避免将 HTML 再包装成 JSON 字符串。该细化取代设计草稿中未定的描述格式；协议边界由 Markdown 解析器识别，并要求围栏真实闭合，不能接受解析器自动补齐的残片。
- 每块有一个根元素，根属性 `data-pi-visualize` 表示内容协议主版本，`data-kit-version` 表示套件主版本，`data-title` 表示可读标题，`data-description` 表示简短文字替代；第一版两个版本均为 `1`。可选 `data-libraries` 声明受支持的本地库标识，未声明时仅使用基础能力。
- 片段允许所需标记、局部样式和经典本地脚本；完整文档壳由宿主拥有。拒绝作者提供的 doctype、html/head/body 壳、base、CSP 覆盖、远程资源与不支持的模块/依赖。预检不等同于 JavaScript 安全审计，安全边界仍由隔离宿主执行。
- 第一版每块最多 64 KiB UTF-8 源码，每个最终回答最多两块、总计不超过 128 KiB；标题不超过 120 个 Unicode 字符，文字替代不超过 500 个。共享库与套件不计入作者源码预算。超限拒绝整个对应作品并给出说明，不能裁剪后执行；模型输出预算可以更小，这些数值是上限。
- 内容身份包含会话、平台消息、块位置和内容摘要。作者提供的标题或 DOM id 不作为持久身份；同一轮多块、相同标题、多轮作品均能区分。
- 不将完整作品再塞入显示日志、工具参数或最新状态副本，不扩大全部事件预算来传作品。已有消息/终态契约保持有限。
- 第一版实现必须先用真实 Dify 验证原生回答保存、传输和按轮恢复，包括大于既有日志裁剪阈值的内容。若平台不支持这条路线，输出可重现证据，再评估附件或存储替代；不得悄悄新增服务、只用浏览器缓存或删减历史恢复承诺。

### 6. 完整回答与历史恢复

- 完整原生回答按平台消息及对应运行绑定，与过程事件合并。修正已有非空裁剪文本挡住完整回答、只补最后一轮原生回答的问题；保留中间消息、思考、工具活动与真实终态。
- live、history、replay 使用同一消息分段、内容校验与宿主组件。完整平台回答替换同条回答的展示内容，不覆盖其他轮次、不重复插入作品、不推导新的可信运行终态。
- 历史恢复逐条使用完整平台回答，支持分页和过程日志缺失。最新 Pi 状态仅恢复它原有负责的会话事实，不能作为旧作品内容来源。
- 源码随原始回答保存，新回答产生新内容身份；后续修改不覆写旧回答。浏览器缓存清除后仍可通过平台历史恢复。
- 历史保留期仍由 Dify 管理。规格承诺的是保留中的会话能恢复作品，不是绕过会话删除或平台保留策略的永久归档。
- 套件主版本和内容协议需要显式处理不兼容。维护第一版作品的可解释性；不支持的版本显示说明与文字替代，不猜测执行。

### 7. 隔离运行、完成门控与生命周期

- 模型片段通过专用宿主组装后在不授予同源能力的脚本 iframe 内运行，不能通过聊天 `v-html` 注入主 DOM。宿主在作者脚本前装入自己的限制、主题与依赖。
- 沙箱不获得父页面 DOM、存储、Dify API key、身份凭据、附件读取或业务工具能力；不授予弹窗、表单提交、下载或顶层导航权限。禁止的能力也不以桥接兼容层重新暴露。
- CSP 和部署策略覆盖连接、脚本、样式、图片、字体、嵌套 frame、导航及其他请求渠道。必须在真实浏览器用网络观测验证无公网请求；只有 sandbox 属性、静态构建检查或字符串黑名单不足以宣称满足此要求。
- 实施前置实验已明确支持边界：作品执行采用 Chromium 154 或更新版本，以及专用静态沙箱文档的 `Connection-Allowlist: ()` 和严格 CSP 响应头；工作台主页面仍可访问 Dify。154 已实测，后续版本需持续回归。旧版或未知浏览器、缺失/不符策略、重定向或预检失败时仅显示文字，不提供绕过运行按钮。UA 和响应头核验只是兼容/部署门控，安全约束由标准浏览器执行响应策略；不能用 JavaScript 模拟。此约束不增加运行后端，静态部署必须保留所需响应头。
- 展示消息通道仅用于就绪、尺寸、错误和宿主主题同步。校验实际 frame、当前会话/消息绑定、类型、频率、载荷大小和尺寸边界；不以 opaque frame 的 `origin` 字符串单独认定可信。
- 生成中只显示占位状态。自动运行要求完整平台回答已收齐、专用块有效且当前运行有可信完成状态；停止、失败、预算耗尽、断线残片不自动运行。
- 平台历史有完整回答但缺少可信过程终态时，可由用户明确点击查看合法作品，同时保持运行状态“未确认”。打开本地作品不补造终态，也不恢复 Agent 执行。
- 对无效、超限、缺资源、运行错误或初始化超时的作品，宿主显示文字替代和简短原因，其他回答继续可读；不自动重发模型请求。
- 自动测量尺寸须限幅并避免父子高度反馈循环。展开/收起保留同一 frame 实例与当前参数；刷新、离开后重开可使用初始参数。会话切换与过期异步回调沿用现有 stale-result 规则。
- 不再需要的 frame、监听器、计时器和 Blob URL 随生命周期释放。用户可关闭异常作品。浏览器 iframe 不提供对任意恶意脚本的强 CPU/内存配额，规格不宣称这一保证；异常演示的恢复行为需在受支持浏览器验证。

### 8. 对话修改与上下文压缩

- 第一版修改走普通用户输入与现有 Pi 轮次；不增加图内发送接口、第二套编辑器或后台模型请求。
- 模型仍持有前文时可按其内容生成修订；旧源码已被上下文压缩移除时，应清楚区分重新生成与基于原源码修改。第一版不增加读取浏览器历史、回填任意作品源码的专用桥。
- 修改后的作品是新回答内容，用户可以比较新旧版本。精确源码编辑、自动定位多作品中的修改对象、跨轮保存图内参数均为后续范围。

### 9. 交付和资源复用

- 插件发布物包含内置技能、按需文档和示例；静态工作台发布物包含宿主、套件和本地资源。两者通过版本清单对齐，不把静态站点变成插件内常驻服务。
- ZCode 开源技能、CSS、基础运行资源可按固定提交复用和适配，保留 Apache-2.0、原有归属、必要 NOTICE 和修改说明。第三方 vendor 分别保留许可证与校验清单。
- 本会话可用的 visualize 技能作为行为和体验参考，不因可读取就假定可直接分发其实现。可分发资源优先使用已核实许可的 ZCode 和第三方库，或自行实现。
- 不整体引入 ZCode 的 React/Electron/文件宿主，也不引入 DeepSeek Harness 的 Session filesystem。复用以内容生成规范、样式、可独立运行资产和宿主边界为单位。

## Testing Decisions

用户已确认主验收边界为工作台可观察的“生成 → 本地交互 → 展开 → 刷新/历史恢复 → 对话修改”。优先测试外部行为和已存在的 Dify/工作台接缝，不为每个 CSS 类、辅助函数或内部消息形状增加镜像测试。

1. **真实 Dify 与工作台整链路为交付依据。** 验证应用图实际输出完整原生回答，并在刷新、清理浏览器缓存、重开会话和两轮以上历史中恢复相同源码摘要。覆盖超过 16,000 字符的作品回答，证明不依赖裁剪日志。
2. **主验收作品。** 生成带到达速度/处理速度滑块的排队演示；调整立即改变图形，暂停/重置有效，展开不丢参数，重开回到初始参数；通过对话增加第二个处理窗口，新旧作品均保留。演示数据明确是讲解模型。
3. **运行套件公开能力。** 通过真实 iframe 验证原生 SVG、使用本地 D3 的图表、Lucide 图标、tabs、tooltip 和必要表单控件；主题切换及 320px/桌面宽度不出现遮挡，关键交互可用键盘操作。检查图表单位、标签和文字替代，不用固定截图像素锁死每个样式。
4. **内容协议与降级。** 使用现有 Markdown/组件测试接缝，覆盖合法内容、多块、普通代码块、用户/工具来源、未闭合围栏、无效属性、未知版本/库、大小边界及多字节文本。无效输入不启动 frame，普通回答仍可阅读。
5. **投影、历史与控制层。** 沿用现有显示契约、投影、历史与 stale-result 测试方式，覆盖裁剪日志与完整回答并存、无过程日志、分页、重复事件、同名作品、会话切换、停止和断流。校验逐消息归属、无重复、无终态伪造及无自动重 POST。
6. **浏览器隔离与资源观测。** 验证父 DOM/存储/凭据访问失败；网络、远程 script/style/image/font、fetch/XHR/WebSocket、导航、嵌套 frame、表单、弹窗和下载均不能绕过约束。观测到外部请求即不通过，不能以“响应不可读”代替“请求未发出”。验证伪造/过期展示消息无效。
7. **错误和生命周期。** 验证脚本异常、资源缺失、初始化超时、反复展开/收起、切换会话以及关闭作品后的释放和恢复行为。CPU 强隔离不纳入承诺，浏览器挂起风险必须如实记录。
8. **内置技能与发布配套。** 沿用技能资格、激活、分页/越界、跨轮恢复及打包测试的既有方式，验证内置技能可发现、示例可生成合法作品、文档宣称的能力与套件一致、发布物包含本地资源和许可。不得把 vendor 源码误作为模型参考资料全量载入。
9. **真实模型验收。** 除固定作品测试外，用当前 Dify provider 实际生成并修改作品，确认参数操作改变演示、技能真实参与且没有虚构测试声明。模型行为采用有限人工验收用例，不要求多次生成源码逐字一致。
10. **回归与证据。** 工作台测试、构建与静态检查应通过；涉及插件时执行相关技能/运行/状态测试与离线打包检查。记录浏览器、Dify/provider、套件和依赖版本，以及真实通过与未验证项。本地 fake、静态页面或截图不能替代真实平台验收。

## Out of Scope

- Dify 自带聊天页面的同等交互宿主；第一版仅自有 Pi Agent 工作台。
- 图内向模型追问、调用工具、提交业务数据、审批、外链打开或远程 API。
- 图内参数跨刷新保存、参数自动进入模型上下文、独立作品库和永久归档。
- 独立 HTML 下载、导出图片/PDF、发布网站、公开分享或外部应用编辑。
- 完整页面生成器、业务看板平台、代码编辑器、可视化源码精确补丁。
- 日历 widget、Tweak 设计面板、设计变体轮播、在线地图和全部上游控件的完整复制。
- 任意 npm/CDN 依赖、动态模块、网络数据加载、本地文件读取、服务端脚本执行。
- Pi Harness 重写、Node/Pi 常驻后端、Electron、独立文件/对象存储服务和新会话状态权威。
- 对任意恶意浏览器脚本的强 CPU/内存隔离保证。

### 实施前置验证与完成判据

第一道验证是原生回答从插件到真实 Dify 历史的完整保存与逐消息绑定；第二道是生成内容在静态 Web 中的隔离及无公网请求。二者均是本规格内的实施工作，不是让用户选择未知平台事实，也不以减少需求替代验证。

全部用户可见链路、内置技能/套件、历史恢复、隔离与离线资源检查通过后才能标为功能完成。若前置验证失败，应保留可重现证据并说明需重开的技术取舍；规格的 `ready-for-agent` 表示范围可实施，不表示相关假设已通过验收。

本规格取代设计草稿中尚未确定的内容编码、资源基线和预算建议；访谈与研究文档保留为决策背景。未创建实施子票，后续可按主验收链路拆票。
