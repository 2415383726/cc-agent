# 人岗匹配

围绕具体岗位和具体人员回答“已证实的适配在哪里、缺什么证据、应补什么”，而不是给人打一个主观总分。应用 `answers-ui` 和 `answers-charts` Skill：用卡片、核验表和必要的量化图把岗位要求与人员证据对齐，Markdown 解释结论和边界。

## 直接调用的工具

| 工具 | 何时调用 | 调用规则 |
|---|---|---|
| 工具 E（轻量检索） | 用户只提供姓名/别名，人员身份不唯一 | 定位人员。出现同名或多个候选时，用一次 `UserPrompt.options` 让用户确认身份。 |
| 工具 C（人员信息） | 人员工号已确定 | 必须调用，优先获取 `全部`。使用级别、工作信息、履历、考核、培训、标签等可解释事实；家庭信息即使返回也不纳入研判。 |
| 工具 F（岗位说明书） | 岗位编码已确定 | 必须调用。提取岗位职责、任职资格、经历、专业/培训与其他明确要求。 |
| tool search（政策检索） | 用户要求资格合规/选任规则，或 F 的要求需要政策口径解释 | 检索具体岗位、资格、年限、选任等关键词。仅使用返回的原文要点；片段不足时标为待核验。 |

不使用高级检索来替代当前人员和岗位的事实核验。人员和岗位都明确后全程直接分析；只有人员身份或岗位编码无法唯一确定时才用 `UserPrompt` 消歧。

## 核验流程

1. 确认分析模式：一人对一岗、多人对一岗，或一人对多个岗位。对象超过 4 人时，保留全量核验表，不任意挑选“最佳人选”。
2. 调用 F，建立岗位要求清单，分为：硬性资格/政策条件、核心职责与必备经历、专业与培训要求、发展性要求。只保留对该岗位有意义的 3–8 项。
3. 对每位确认人员调用 C，提取同口径的工作信息、级别、履历、考核和培训证据。
4. 每项要求只标记：`已证实满足`、`部分证实`、`信息不足待核验`、`已知不满足`。最后一种必须有明确事实和适用规则，不能由模型推断。
5. 区分硬条件与发展性差距。硬条件未证实时，不得用优势或培训记录抵消；发展性差距可提出补强建议。
6. 写出适配结论、风险边界和下一步核验/培养动作。任用、调整、写入和审批仍走既有权限流程。

## 研判准则

| 要求类别 | 可用证据 | 正确表达 | 禁止表达 |
|---|---|---|---|
| 资格与级别 | C 的级别/工作信息、F、政策 | “已取得的级别/资格与要求的对应关系为…” | “级别高所以必然适任” |
| 核心职责 | F 的职责、C 的实际工作与履历 | “具有承担相同/相近职责的直接记录” | 把相邻领域经历写成完全满足 |
| 经历与年限 | 履历起止时间、岗位类别、F/政策要求 | “已核验的相关经历年限为…” | 缺失日期时虚构累计年限 |
| 考核与成果 | 同周期、同口径的考核记录及已留痕成果 | “该记录可作为履职证据之一” | 跨周期直接排名或把一次考核定性为能力 |
| 培训与专业 | 培训、资格、专业和岗位要求 | “对知识/资格要求形成支持证据” | 培训次数等于胜任程度 |
| 标签 | 正式且可解释的标签 | 仅作补充线索或检索条件 | 仅凭标签作适配判断 |

家庭、健康、联系方式和无业务必要的敏感信息不得出现于任何匹配依据、卡片或结论。没有岗位编码或岗位说明书时，只能做“人员经历与用户描述岗位的关联观察”，必须明确不能完成正式适配核验。

## 最终呈现

1. **结论摘要（Markdown）**：先说明岗位、对象和数据范围，再用 3–5 条写已证实适配点、关键待核验项和建议。
2. **岗位要求概览（`cc-record`）**：岗位名称/编码、核心职责、关键资格、政策口径状态与分析范围。字段保持短而具体。
3. **要求—证据核验表（`cc-table`）**：每行一个要求，列出要求类别、岗位要求、人员已知证据、核验状态、证据边界和建议动作。这是单人匹配的核心界面。
4. **多人横向对照（`cc-compare`，可选）**：仅在 2–4 名候选人对同一岗位时使用，按相同要求比较；只高亮可证实事实，不宣布“最优”。超过 4 人时使用 `cc-table` 展示全部对象。
5. **量化证据（最多 1 个 `cc-chart`，可选）**：只有相关经历年限、现岗年限或同口径数值考核可比较时，使用横向 bar，并标明单位、统计日期和分母。无可靠数值时不生成 Chart。
6. **关键经历（`cc-timeline`，可选）**：只有任职先后或关键经历衔接影响判断时使用，不把完整简历逐条搬入时间线。
7. **适配研判与建议（Markdown）**：按“已证实 / 待核验 / 可补强”分组。没有足够证据时写“暂不能判断”，不以模型判断补足。

## 交付前检查

- [ ] 岗位与人员身份已唯一确认，或已明确限制。
- [ ] 已调用 F 和 C；所有核验项均可回溯到岗位说明、政策或人员记录。
- [ ] 硬性资格、核心职责、发展性要求没有混为一类。
- [ ] 未用家庭、敏感信息、主观评分或标签代替证据。
- [ ] 每个 UI/Chart 都有独立信息任务，没有复制同一数据。
- [ ] 结论未替代组织决定、资格认定或审批。
