# 05: Dify 工具调用、通用工具卡与附件闭环

**What to build:** 用户提出需外部工具处理的问题，Pi 调用本轮 Dify 授权工具、消费结果并继续回答，工作台展示一次执行及真实附件。

**Blocked by:** [03 Pi 驱动问答与跨轮续聊](03-pi-dify-conversation.md)

**Status:** ready-for-agent

**Version:** v2；用户已确认拆分并发布。按必要前置完成情况选择实施前沿；当前尚未实施。

**Parent:** [Agent 工作台规格 v2](../spec.md)

**Spec coverage:** US08、US09、US12、US13、US14、US15、US17；V06、V09、V18。这是本票涉及的行为，不表示本票单独签收整个验收场景；最终平台证据由 17、18 补齐。

## Acceptance criteria

- [ ] 注册本次 Dify 注入工具并保持当前身份，默认串行；工具开始/可用更新/完成/错误按原 call ID 显示，未知类型也有通用参数/结果卡。
- [ ] 完整参数验证后才执行；未知工具、工具异常和无效参数均有配对结果，下次模型请求前每个 assistant tool call 恰有对应结果。
- [ ] 调用成功后模型能消费结果继续回答；执行与输出投影分离，隐藏展示不改变工具权限或是否执行。
- [ ] 保留 repeated-halves 与语义 JSON 去重；Dify 自身转发的产物不增加第二路径，页面不会重复显示同一执行/文件。
- [ ] 完成上传/files 映射及工具返回附件的查看/下载链路，必要安全引用可跨历史展示；files 元数据不被解释为已经读取内容。
- [ ] 区分展示预算与送模结果预算，提供受限结果投影和初始执行计数；不将 blob 原文或大对象重复塞入会话历史。
- [ ] 不注册通用本地 bash/read/write/edit 或 stdio MCP；外部文件、执行、检索能力只来自本次授权工具。
- [ ] 完成策略入口→真实工具 fake→配对历史→浏览器工具卡/附件验证，并在目标 Dify 样本验证产物唯一交付。

## Implementation context

- 本票完成普通 Dify 工具与基础故障处理；复杂 provider 流由 06、远程 MCP 由 09、统一预算由 10 扩展。
- 复用旧插件中符合约束的 Dify 适配行为，不复制完整调度循环或保留旧卡片 schema。
- 当前只有少量骨架和依赖导入，前置票是否完成须检查实际验收记录。v2 是唯一范围依据，不恢复旧 AG-UI 双入口、Tasks、六命令或旧前端兼容要求。
- 每票包含自身完整行为及必要验证，优先从策略入口、真实 SDK 消息和浏览器观察；只给易变接入点补有限契约测试，不为每个内部 helper 建测试。

## Verification

覆盖成功、异常、无效 JSON/未知工具、重复半段、等价 JSON、文件产物及上传元数据，观察实际工具次数、模型历史和页面唯一内容。
