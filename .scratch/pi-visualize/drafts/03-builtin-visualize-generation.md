# 03: 内置 visualize 技能生成和修订作品

发布状态：用户已确认，保留为历史草稿；实施请使用[正式票](../issues/03-builtin-visualize-generation.md)。

**What to build:** 用户明确请求交互讲解，或助手判断有助于理解时，由真实模型使用内置 visualize 应用技能生成可运行作品；用户通过普通对话修改得到新作品，旧回答中的作品仍可重开。

**Blocked by:** 02 — 使用内置样式与本地资源完成交互讲解。

依据：[规格 v1](../spec.md) 的内置技能、生成质量、对话修改与插件/套件配套要求。

## Acceptance criteria

- [ ] `visualize` 随插件发布并通过现有应用技能机制可发现、模型激活、用户调用、受限资源分页读取及跨轮资格恢复；工作台显示真实技能活动，既有技能边界与异常行为保持有效。
- [ ] 技能入口说明生成时机与核心步骤；按需资料覆盖内容协议、实际样式/控件目录、库 API 与至少原生 SVG、D3 图表、控件组合三类完整示例。所有示例使用 02 已提供的真实能力。
- [ ] 资料指导有意义首屏、一个主要图解、必要控件、参数实际影响图形、标签/单位、主题与可访问性；简单事实和表格请求保持直接表达，不因存在可视化技能就强行生成作品。
- [ ] 技能输出原始专用片段，遵守版本、字段与体积上限，复用公共套件；不要求模型写本地文件、执行渲染脚本、复制 vendor 或调用 OpenAI/ZCode 专用桥，也不虚构已执行测试。
- [ ] 第三方 CSS/JS 等运行资产不进入插件技能资料的全文扫描或模型上下文；插件文档版本与工作台公共套件一致，实际发布物包含技能资料与示例。
- [ ] 用当前 Dify provider 真实生成排队演示并在工作台调参、暂停、展开和刷新；图内操作只改变本地状态，不产生模型请求、工具调用或跨轮参数保存。
- [ ] 通过正常下一轮输入要求增加第二个处理窗口，生成新内容身份；旧作品保持可查看，新旧作品均能从平台历史恢复。模型上下文已缺旧源码时，明确重新生成与精确编辑的差别，不增加浏览器历史读取或任意源码回填桥。
- [ ] 对主动生成、明确请求和普通问答使用有限真实模型验收用例，记录真实输出与可观察结果，不以固定回放冒充模型生成，也不要求源码逐字一致。
- [ ] 相关技能/运行测试与离线插件打包检查通过；样例在实际宿主中运行，文档没有宣称未提供的日历、Tweak、远程资源或 Agent 操作能力，现有状态与审批契约不变。

## Scope notes

依赖 02 是因为模型资料必须基于可运行且已验收的套件。此票不提供精确源码编辑器、跨轮 widget state 或图内继续对话按钮。
