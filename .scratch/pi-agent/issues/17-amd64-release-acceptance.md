## Acceptance criteria

- [ ] 在干净 Linux amd64、匹配 Python 3.12 插件执行器的目标 Dify 环境，断网依赖条件下安装最终一个 difypkg，不使用开发机缓存补齐。
- [ ] 静态前端不依赖 CDN/外部脚本，模型与业务工具仅走授权可达服务；记录环境、网络条件、版本、插件与静态资产 hash。
- [ ] 执行普通回答、复杂工具/附件、远程 MCP、技能、预算、长上下文/溢出、问卷/审批及跨轮恢复的代表业务组合。
- [ ] 刷新/切换、重复/过期答复、批准后策略变化、未知写操作、客户端停止/断流与保存失败均按规格表现。
- [ ] 核对 V01—V19 的组合结果，并对 amd64 的 V20、业务 V22 提供实际证据；前序 fake 和源码研究不是替代验收。
- [ ] 同条件记录新旧插件的实际模型/工具次数、已报告 token、耗时、包大小和任务完成情况，说明配置差异和限制，不编造性能阈值或提升。
- [ ] 未通过项逐项保留且不宣称首版完成；本架构成功不签收 arm64，亦不自动部署生产或开始迁移旧会话。

## Implementation context

- 本票验证最终功能及最终依赖，不以 04 的基础启动包作为完整包；环境准备和执行证据必须可复现。
- 比较旧插件仅用于业务与效率基线，不改变旧插件或增加新功能。
- 当前只有少量骨架和依赖导入，前置票是否完成须检查实际验收记录。v2 是唯一范围依据，不恢复旧 AG-UI 双入口、Tasks、六命令或旧前端兼容要求。
- 每票包含自身完整行为及必要验证，优先从策略入口、真实 SDK 消息和浏览器观察；只给易变接入点补有限契约测试，不为每个内部 helper 建测试。
