## Acceptance criteria

- [ ] 支持现有 sse 与 streamable_http 远程配置，通过本轮 headers 和用户身份发现、注册并调用普通模型工具。
- [ ] 两用户、两运行不共享凭证、工具目录或连接；敏感 headers 不进入提示、工具元数据、状态或日志。
- [ ] 保留 MCP Apps 可见性过滤：App 专用入口/helper 不作为普通工具暴露，同时可见的普通业务工具仍可用。
- [ ] Pi 执行 MCP 调用并继续回答，工具异常、参数错误仍有配对结果，遵守与 Dify 工具一致的串行/结果约束。
- [ ] 直连 MCP blobs 通过共同宿主交付一次，前端能访问对应产物；不借用 Dify 工具自动转发造成重复。
- [ ] 普通完成、连接失败、工具失败及消费者提前关闭均释放本轮远程资源，不能让下一运行继承失效连接。
- [ ] 不增加本地 stdio MCP、启动服务端进程、通用本地 I/O 或 MCP Apps 宿主。

## Implementation context

- 按已确认规格实施：社区 Python Pi core/harness 0.6.0 为初始基线，单项目单插件双入口；Dify 持有模型/工具授权与唯一跨轮状态。内部只提供认知工具，不恢复已移除能力。
- 普通执行路径在本票完成；MCP 的跨轮确认、恢复执行、恢复后的 blob 交付和 unknown 处理由 13 完成。
- 身份只属于当前 Dify 运行，不把原始 Session 或 headers 序列化为会话恢复配置。
