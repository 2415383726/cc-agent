# 以语义事件隔离执行与双协议输出

旧实现的循环、压缩及中断模块调用协议 Writer，使输出细节渗入执行流程。新插件改为内核单向产生少量类型化语义事件，由每轮选定的 AG-UI 或 Dify 原生输出 Adapter 消费；入口能力在启动时独立配置，内核不根据输出协议名改变行为。

状态变量与附件由共同 Dify 宿主交付，先保存和输出有效状态再发布终态，避免输出 Adapter 重复承担持久化或产物转发。接受各 Adapter 维护本轮渲染状态的成本，以换取同一执行轨迹可独立投影和验证的接口；不增加事件总线或双内核运行模式。

用户于 2026-10-29 确认同一项目、一个插件包提供 AG-UI/Dify 原生两个独立入口，共享 Pi 执行内核；按目标架构构建对应包。入口能力与输出编码分开装配，主验收接口是 Dify 策略入口及跨轮状态恢复。未来如有独立发布、权限或依赖差异，可重新评估拆包；首版不复制为两个独立项目。

同日后续用户允许整体替换前端与协议，固定 AG-UI 入口及旧界面兼容不再是硬要求，见 [ADR-0007](0007-agent-workbench-scope.md)。执行与输出隔离、共同状态/产物交付继续成立；具体事件子集和前端复用以新方向验证为准。
