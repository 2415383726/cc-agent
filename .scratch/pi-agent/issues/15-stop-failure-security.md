# 15: 停止、断流与安全失败收尾

**What to build:** 用户停止、网络断开或模型/工具失败时，工作台准确区分已结束、等待与未确认，资源释放且不泄露秘密。

**Blocked by:** [06 模型流兼容与工具参数正确执行](06-provider-streaming.md)；[14 远程审批恢复与未知结果核实](14-mcp-resume-unknown.md)

**Status:** ready-for-agent

**Version:** v2；用户已确认拆分并发布。按必要前置完成情况选择实施前沿；当前尚未实施。

**Parent:** [Agent 工作台规格 v2](../spec.md)

**Spec coverage:** US16、US17、US32、US37、US38、US39；V03、V07、V14、V17、V18。这是本票涉及的行为，不表示本票单独签收整个验收场景；最终平台证据由 17、18 补齐。

## Acceptance criteria

- [ ] 客户端停止通过实际 Dify 停止接口尽力传播，宿主感知后停止新工作并释放 SDK/MCP/输出资源；不能将关闭浏览器当作业务已取消。
- [ ] 复杂模型流、工具执行、审批恢复、等待和状态输出阶段的取消/异常都产生准确可用状态或明确未确认，不伪造成功。
- [ ] 状态保存/输出失败不能发布正常完成；安全 agent_failed JSON 包含代码、阶段与 run ID，不输出 traceback 或原始异常。
- [ ] 没有可信终态的断流在刷新/历史恢复后仍标为未确认，不自动重发业务请求、批准或问卷答复。
- [ ] 验证两次独立/并行请求的身份、连接、消息与 pending 隔离；客户端对同一对话限制重复发起，但不声称有多客户端原子锁。
- [ ] 配置凭证不进入提示、状态、日志、工具元数据和最终输出；使用带 canary 的错误/配置样本检查允许字段投影，不转储 provider headers/正文。
- [ ] 保留所有工具调用配对与已完成结果，unknown 不擅自变失败/未执行；清理失败不能覆盖主要业务事实。
- [ ] 通过策略、SDK 和浏览器覆盖流中止、同步 SDK 延迟、远程失败、保存失败与重连；每个场景记录真实可控制的停止边界。

## Implementation context

- 前序票已包含各自基本清理和错误行为，本票整体验证复杂流/远程恢复/浏览器断开的交叉路径，不是把所有错误处理拖到最后。
- 不得引入额外常驻控制网关来伪造实时取消保证。
- 当前只有少量骨架和依赖导入，前置票是否完成须检查实际验收记录。v2 是唯一范围依据，不恢复旧 AG-UI 双入口、Tasks、六命令或旧前端兼容要求。
- 每票包含自身完整行为及必要验证，优先从策略入口、真实 SDK 消息和浏览器观察；只给易变接入点补有限契约测试，不为每个内部 helper 建测试。

## Verification

注入阶段性失败与延迟、执行真实停止/断开动作，检查后续真实调用、资源、快照/终态和 secret canary；记录无法强制取消的操作为准确未知。
